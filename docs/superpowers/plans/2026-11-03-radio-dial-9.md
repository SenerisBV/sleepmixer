# Plan 9: Esoterica DM, the radio dial on the phone — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An iPhone app, Esoterica, whose only control is a radio dial with three stations (The Lantern Accords, Backward Lesson One, The Orchard Light) that drift away live over the night, installed on the operator's phone.

**Architecture:** Python cuts the existing raw takes into 1–2 minute segments and exports a station bundle (no voicing, no credits). In Swift, `NightPlan` gains the pure night logic (the drift, the drift clock with resets, each station's broadcast schedule, the dial's gains). A new `NightRadio` library renders every station and the static continuously **on a background render thread** into lock-free ring buffers, about 1.5 s ahead. The audio callback only mixes those rings with the dial's gains and a master fade. Because the DSP never runs on the audio thread, the known allocation hazards of the scenes do not block this plan. A SwiftUI app generated by XcodeGen hosts the dial, the audio session and the lock-screen controls.

**Tech Stack:** Python 3 (pipenv, click, numpy, soundfile, pytest); Swift 6, the `NightEngine` package (macOS 15 / iOS 18), `Synchronization` (`Atomic`, `Mutex`), AVFoundation (`AVAudioEngine`, `AVAudioSourceNode`, `AVAudioSession`), MediaPlayer (`MPRemoteCommandCenter`), SwiftUI, XcodeGen 2.x, Xcode 27.

**Spec:** `docs/superpowers/specs/2026-11-03-radio-dial-design.md` (builds on `2026-11-02-am-night-design.md` and `2026-11-02-esoterica-design.md`).

## Global Constraints

- Work on branch `feat/radio-dial` (already created, from `feat/esoterica-pace`).
- No voicing and no API calls in this plan: zero ElevenLabs or Cartesia credits. Tests never touch the network.
- The raw takes in `esoterica/library/` are never modified or deleted; the `[segment]` marker must not make any take stale.
- The planner (`NightPlan`) has no audio imports: no AVFoundation and no `NightDSP` (the existing `ImportGuardTests` enforces this; extend it to new files).
- Nothing sudden: every on, off, pause, play, reset and tuning change is a fade. The values are below. Nothing that goes wrong makes a sound. A missing segment file is silence, never a crash or a click.
- The audio render callback never allocates, never locks and never does file I/O. Only the render thread does.
- Never fall through to the phone speaker on route loss.
- Sample rate 44100 Hz mono inside the engine, duplicated to stereo at the output.
- Station bundles are generated, not committed: `ios/Esoterica/Stations/` is git-ignored (`*.wav` already is; add the directory).
- Every placeholder value below is recorded in `docs/project-state.md` (new section "Plan 9") when built, by name, value and file.

- Python tests: `pipenv run pytest -q`. Swift tests: `cd swift && swift test`. The app: `xcodegen` in `ios/`, then `xcodebuild`.

## Review Focus

1. **The wheel is touched constantly while browsing.** The drift must stay at bedtime clarity during browsing, and it must not jump: each touch's fade starts from the depth just before that touch. *Test in Task 4:* `browsingNeverDeepens`.
2. **The radio is switched off and on again mid-night.** It must behave as a fresh night: clock zero, new random start points, no stale ring audio. *Test in Task 8:* `offThenOnStartsFresh`.
3. **A segment file is missing or unreadable in the bundle.** That segment is silence for its scheduled length and the schedule carries on. *Test in Task 7:* `missingSegmentIsSilence`.
4. **The render thread falls behind**, for example at the first segment load. The callback outputs silence for the missing frames (faded, not a click) and never blocks. *Test in Task 8:* `underrunFadesToSilence`.
5. **A cut lands inside a word**, for example because a thought boundary has no pause. Every cut must sit inside a detected pause, and the mark moves to the nearest pause. *Test in Task 2:* `cut_moves_to_nearest_pause`.

**Files:**

- Produces:
  - `find_pauses(x: np.ndarray, sr: int) -> list[tuple[float, float]]`: (start, end) seconds of inner silences of at least 0.25 s, using `PAUSE_THRESHOLD_DB` and `PAUSE_WIN_S`.
  - `cut_times(x, sr, fractions: list[float]) -> list[float]`: for each expected fraction of the take, the midpoint of the chosen pause.
  - `export_station(script, library: Path, out: Path) -> dict`: writes `out/<id>/sNN.wav` (1-based, 2 digits) and `out/<id>/station.json`, and returns the JSON dict.
  - CLI: `sleepmix esoterica bundle <id>... --out ios/Esoterica/Stations`.
  - `station.json`: `{"id": str, "title": str, "segments": [{"file": "s01.wav", "seconds": float}]}`.

**Choosing a cut:** the expected time is `fraction × take duration`, where `fraction` is the share of the passage's spoken characters before the segment's first paragraph. Score each pause by `pause length − 0.02 × |midpoint − expected|`, and pick the best within ±20% of the take's duration of the expected time. If none qualifies, take the pause nearest the expected time. **Every cut is the midpoint of a pause.** A segment never spans two passages: passage boundaries are always cuts, and the takes are separate files.

**Rendering:** each segment's slice of the raw take goes through the same chain as `render_character`: `stretch_pauses(slice, SR, script.pause_stretch)`, then `apply_character(..., character_seed(script.id, passage_index * 100 + segment_number))`, then `_edges(…, RENDER_EDGE_S)`, then `normalise`. Resample to 22050 Hz and write 16-bit PCM.

**Interfaces:**
- Produces:

```swift
public struct DriftLevel: Equatable, Sendable { public var free: Double; public var ratchet: Double }
public enum Drift {
    public static func level(clock: Double, seed: UInt64) -> DriftLevel   // table values
    public static func bedWarp(_ l: DriftLevel) -> WarpDepth
    public static func voiceDistance(_ l: DriftLevel) -> Double
    public static func voiceGainDB(_ l: DriftLevel) -> Double
    public static func channel(_ l: DriftLevel) -> ChannelSettings
    public static func staticGainDB(_ l: DriftLevel) -> Double
    public static func segmentGap(_ l: DriftLevel) -> Double
    public static func endWait(_ l: DriftLevel) -> Double
}
/// Engine seconds (since the radio clicked on) -> drift. Thread-safe (Mutex); touches arrive from the UI.
public final class DriftClock: Sendable {
    public static let settleSeconds = 60.0, resetFadeSeconds = 4.0
    public init(seed: UInt64)
    public func touch(at second: Double)            // a wheel turn; also called once at 0 when switched on
    public func level(at second: Double) -> DriftLevel
}
```

**Level at second t:**
- Let `T` be the latest touch ≤ t, with `d0` the level recorded just before it (computed at `touch` time).
- `c = max(0, t − T − settleSeconds)`, and `target = Drift.level(clock: c)`.
- For `t − T < resetFadeSeconds`, interpolate `d0 → target` with a raised cosine; otherwise use `target`.
- Touches must arrive in non-decreasing order; an older one is ignored.
- For `t` before the first touch, the result is level 0.

### Task 8: The live engine (NightRadio)

**Files:**
- Create: `swift/Sources/NightRadio/SPSCRing.swift`, `Renderer.swift`, `RadioEngine.swift`
- Test: `swift/Tests/NightRadioTests/RadioEngineTests.swift`, `SPSCRingTests.swift`

**Interfaces:**
- Produces:

```swift
public final class SPSCRing: @unchecked Sendable {     // Atomic<Int> read/write indexes, preallocated
    public init(capacity: Int)
    public func write(_ src: UnsafeBufferPointer<Float>) -> Int    // frames written
    public func read(into dst: UnsafeMutableBufferPointer<Float>) -> Int  // frames read; never blocks
    public var available: Int { get }
}
public final class RadioEngine: @unchecked Sendable {
    public init(bundles: [String: StationBundle], manualRendering: Bool = false)
    public func setNeedle(_ needle: Double)        // from the UI; stored atomically
    public func wheelTouched()                     // -> DriftClock.touch(at: nowSecond)
    public func pause(); public func play()        // master fade, the clock keeps running
    public var nowSecond: Double { get }           // frames played / 44100
    public var isOn: Bool { get }
    /// Test hook (manual rendering mode): render `frames` of output.
    public func renderManually(frames: Int) throws -> [Float]
}
```

**How it fits together:**
- **Switching on and off:** `setNeedle` crossing out of the off zone switches on. That creates a new `DriftClock(seed: random)`, touches it at 0, starts the `Renderer` thread and the `AVAudioEngine`, and fades in over 2 s. Crossing into the off zone fades out over 1.5 s, then stops the engine and the thread and discards the rings.
- **The render thread:** one `Thread` at `.userInteractive` QoS. It keeps every ring (three stations plus static) filled to 1.5 s in 2048-frame blocks, sleeping 5 ms when full.
- **The audio callback** (an `AVAudioSourceNode`): it reads its block from each ring, mixes with `Dial.gains` from the atomic needle (each gain smoothed per sample with a 30 ms one-pole), applies the master fade, and writes both channels.
- **Underruns:** on a short read, the missing frames are zeros, with a 5 ms fade on the last real frames.
- **The clock:** `nowSecond` advances by frames output.
- **Thread rules:** no locks or allocation in the callback; the needle, master target and frame counter are `Atomic`.

- [ ] **Step 1: Write the failing tests.**
  - `ringRoundTrips`: write 5000, read 5000, identical.
  - `ringNeverOverwrites`: writing more than the capacity returns the capacity.
  - `offIsSilent`: needle 0, `renderManually(44100)` gives all zeros.
