# sleepmix Elm Shell Implementation Plan (Plan 3a)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working Elm application served by the existing server — browse the library, import a song, see its waveform and detected loop, and separate it with live progress.

**Architecture:** Elm compiles to a single `app.js` committed into `sleepmix/static/`, so `pip install` users never need Node. The compiler is the verification mechanism: `/api/schema` and every API response decode into closed union types, and a server field the UI does not handle fails the build rather than rendering nothing. One JavaScript port module owns the `EventSource` connection, because `elm/http` cannot open one.

**Tech Stack:** Elm 0.19.2, `elm-test`, plain ES modules for ports. No bundler, no `node_modules` in the shipped artefact.

**Spec:** `docs/superpowers/specs/2026-08-03-sleepmix-ui-design.md`
**Preceded by:** Plans 1, 2a and 2b — all complete and merged. The API is feature-complete.

## Global Constraints

- **Elm 0.19.2.** Runes-style churn does not exist here; there is one API and it has been stable since 2019. Do not reach for `elm-ui`, `elm-css` or any framework-adjacent package — `elm/html` and `elm/svg` only.
- **The compiled bundle is committed.** `sleepmix/static/app.js` is a build artefact that ships in the wheel. Building requires the `elm` binary; *installing* sleepmix must not.
- **No `node_modules` in the shipped artefact.** `elm-test` is a development tool only.
- **Ports carry JSON, never binary.** Elm never touches audio bytes.
- Python side: Python ≥3.10, no new runtime dependencies, `fastapi`/`uvicorn`/`starlette` only inside `sleepmix/server/`.
- All persistent state under `paths.data_dir()`.
- Existing Python style: module docstring explaining *why*, `from __future__ import annotations`, private helpers prefixed `_`.
- The CLI and the whole existing Python suite (203 tests) must keep passing.

```elm
module Main exposing (main)

{-| The sleepmix interface.

Elm rather than a JavaScript framework because most of this is written by an
agent, and the compiler turns a whole class of mistakes — a renamed field, an
unhandled case — into build failures rather than into something that renders
blank and says nothing.

Where Elm stops: ports are asynchronous and JSON-only, so the Web Audio engine
and the EventSource connection live in hand-written JavaScript. Elm sends
parameters out and receives outcomes back; it never touches audio bytes.
-}

import Browser
import Html exposing (Html, div, h1, p, text)
import Html.Attributes exposing (class)
import Http
import Json.Decode as Decode


type alias Model =
    { health : Health }


type Health
    = Checking
    | Ready String
    | Unreachable String


type Msg
    = GotHealth (Result Http.Error String)


main : Program () Model Msg
main =
    Browser.element
        { init = init
        , update = update
        , subscriptions = always Sub.none
        , view = view
        }


init : () -> ( Model, Cmd Msg )
init _ =
    ( { health = Checking }
    , Http.get
        { url = "/api/health"
        , expect = Http.expectJson GotHealth (Decode.field "version" Decode.string)
        }
    )


update : Msg -> Model -> ( Model, Cmd Msg )
update msg model =
    case msg of
        GotHealth (Ok version) ->
            ( { model | health = Ready version }, Cmd.none )

        GotHealth (Err err) ->
            ( { model | health = Unreachable (httpErrorToString err) }, Cmd.none )


httpErrorToString : Http.Error -> String
httpErrorToString err =
    case err of
        Http.BadUrl url ->
            "bad url: " ++ url

        Http.Timeout ->
            "the server took too long to answer"

        Http.NetworkError ->
            "could not reach the server"

        Http.BadStatus code ->
            "the server answered " ++ String.fromInt code

        Http.BadBody detail ->
            "could not read the server's answer: " ++ detail


view : Model -> Html Msg
view model =
    div [ class "app" ]
        [ h1 [] [ text "sleepmix" ]
        , case model.health of
            Checking ->
                p [] [ text "Connecting…" ]

            Ready version ->
                p [] [ text ("Connected to sleepmix " ++ version ++ ".") ]

            Unreachable reason ->
                p [ class "error" ] [ text ("Not connected — " ++ reason) ]
        ]
```

`httpErrorToString` exists because `Http.Error` is a union: the compiler forces every variant to be handled, and a UI that says "could not reach the server" is worth more than one that says "error".

Create `ui/ports/events.js`:

```javascript
// EventSource bridge.
//
// Elm cannot open an EventSource — elm/http has no server-sent-events support
// — so this module owns the connection and forwards parsed events inward. It
// stays deliberately thin: no state beyond the open connections, no decisions,
// no retry policy of its own beyond the browser's own reconnection.
//
// A later change adds the audio engine as a sibling module. Both keep the same
// shape: Elm sends parameters out, JavaScript sends outcomes back, and nothing
// but JSON crosses the boundary.

export function wire(app) {
  const open = new Map();

  if (app.ports && app.ports.watchJob) {
    app.ports.watchJob.subscribe((jobId) => {
      if (open.has(jobId)) return;
      const source = new EventSource(`/api/jobs/${jobId}/events`);
      open.set(jobId, source);

      source.onmessage = (event) => {
        try {
          app.ports.jobEvent.send(JSON.parse(event.data));
        } catch (err) {
          console.error("sleepmix: unparseable job event", err);
        }
      };

      source.onerror = () => {
        // The stream closes normally once a job reaches a terminal status, so
        // an error here is usually just that. Close rather than let the
        // browser reconnect to a finished job forever.
        source.close();
        open.delete(jobId);
      };
    });
  }

  if (app.ports && app.ports.stopWatchingJob) {
    app.ports.stopWatchingJob.subscribe((jobId) => {
      const source = open.get(jobId);
      if (source) {
        source.close();
        open.delete(jobId);
      }
    });
  }
}
```

The `app.ports && app.ports.x` guards matter: Elm only generates a port if the Elm code actually uses it, so wiring a port the application does not yet declare would throw at startup. Task 5 declares them.

Create `ui/hash_sources.py`:

```python
#!/usr/bin/env python3
"""Print a hash of everything that goes into the Elm bundle.

`sleepmix/static/app.js` is committed, so it can drift from the sources it was
built from and nothing would notice. The Makefile records this hash beside the
bundle and a test recomputes it — mtimes cannot do the job, because a fresh
clone gives every file the same checkout time in arbitrary order.

Both the build and the test invoke *this* script, so there is no second
implementation to disagree with.
"""
import hashlib
import pathlib
import sys

ROOT = pathlib.Path(__file__).resolve().parent.parent


def main() -> int:
    inputs = sorted((ROOT / "ui" / "src").rglob("*.elm"))
    inputs += [ROOT / "ui" / "elm.json", ROOT / "ui" / "ports" / "events.js"]
    digest = hashlib.sha256()
    for path in inputs:
        # Include the name: renaming a module changes the bundle even when the
        # bytes of every file are unchanged.
        digest.update(str(path.relative_to(ROOT)).encode())
        digest.update(path.read_bytes())
    print(digest.hexdigest())
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

```elm
module Api exposing
    ( Job, JobStatus(..), Song, SeparationStatus(..)
    , isFinished, job, song, statusLabel
    )

{-| Types and decoders for the sleepmix API.

This is the seam where an untyped HTTP response becomes a typed value, and it
is deliberately strict: an unrecognised status fails the decode rather than
falling back to a catch-all. A server that grows a status this application does
not handle should say so loudly, not render an empty row.
-}

import Json.Decode as Decode exposing (Decoder)
import Json.Decode.Pipeline as Pipeline


type SeparationStatus
    = NotSeparated
    | Separating
    | Separated
    | Fallback String
    | SeparationFailed String


type alias Song =
    { id : String
    , path : String
    , title : String
    , durationS : Float
    , sampleRate : Int
    , separationStatus : SeparationStatus
    , stems : List String
    , addedAt : String
    }


type JobStatus
    = Queued
    | Running
    | Done
    | Cancelled
    | Failed String


type alias Job =
    { id : String
    , kind : String
    , status : JobStatus
    , fraction : Float
    , message : String
    , songId : Maybe String
    }


isFinished : JobStatus -> Bool
isFinished status =
    case status of
        Queued ->
            False

        Running ->
            False

        Done ->
            True

        Cancelled ->
            True

        Failed _ ->
            True


statusLabel : SeparationStatus -> String
statusLabel status =
    case status of
        NotSeparated ->
            "not separated"

        Separating ->
            "separating…"

        Separated ->
            "separated"

        Fallback _ ->
            "one stem only"

        SeparationFailed _ ->
            "separation failed"


song : Decoder Song
song =
    Decode.succeed Song
        |> Pipeline.required "id" Decode.string
        |> Pipeline.required "path" Decode.string
        |> Pipeline.required "title" Decode.string
        |> Pipeline.required "duration_s" Decode.float
        |> Pipeline.required "sample_rate" Decode.int
        |> Pipeline.custom separationStatus
        |> Pipeline.optional "stems" (Decode.nullable (Decode.list Decode.string) |> Decode.map (Maybe.withDefault [])) []
        |> Pipeline.required "added_at" Decode.string


separationStatus : Decoder SeparationStatus
separationStatus =
    Decode.map2 Tuple.pair
        (Decode.field "separation_status" Decode.string)
        (Decode.field "separation_reason" (Decode.nullable Decode.string))
        |> Decode.andThen
            (\( status, reason ) ->
                case status of
                    "pending" ->
                        Decode.succeed NotSeparated

                    "running" ->
                        Decode.succeed Separating

                    "done" ->
                        Decode.succeed Separated

                    "fallback" ->
                        Decode.succeed (Fallback (Maybe.withDefault "no reason given" reason))

                    "failed" ->
                        Decode.succeed (SeparationFailed (Maybe.withDefault "no reason given" reason))

                    other ->
                        Decode.fail ("unknown separation_status: " ++ other)
            )


job : Decoder Job
job =
    Decode.succeed Job
        |> Pipeline.required "id" Decode.string
        |> Pipeline.required "kind" Decode.string
        |> Pipeline.custom jobStatus
        |> Pipeline.required "fraction" Decode.float
        |> Pipeline.required "message" Decode.string
        |> Pipeline.required "song_id" (Decode.nullable Decode.string)


jobStatus : Decoder JobStatus
jobStatus =
    Decode.map2 Tuple.pair
        (Decode.field "status" Decode.string)
        (Decode.field "error" (Decode.nullable Decode.string))
        |> Decode.andThen
            (\( status, err ) ->
                case status of
                    "queued" ->
                        Decode.succeed Queued

                    "running" ->
                        Decode.succeed Running

                    "done" ->
                        Decode.succeed Done

                    "cancelled" ->
                        Decode.succeed Cancelled

                    "failed" ->
                        Decode.succeed (Failed (Maybe.withDefault "no detail given" err))

                    other ->
```

```elm
module Waveform exposing (Bar, barFor, view)

{-| Peaks as SVG.

SVG rather than canvas because a canvas would mean escaping Elm's virtual DOM
and managing pixels through a port, while the loop-region handles this needs
are just mouse events mapped to messages — which is a state machine Elm models
well. A few thousand rects is well within what a browser draws comfortably.

Min *and* max are drawn rather than absolute peak, so an asymmetric signal
looks asymmetric. That is a real cue when picking a loop region by eye.
-}

import Svg exposing (Svg)
import Svg.Attributes as A


type alias Bar =
    { y : Float, height : Float }


{-| Where one peak pair sits in a viewport of the given height.

The vertical axis is inverted — SVG grows downward, audio does not — so a peak
of +1.0 is at y=0. A silent bucket still gets a hairline: a waveform with holes
in it reads as missing data rather than as silence.
-}
barFor : { height : Float } -> ( Float, Float ) -> Bar
barFor { height } ( low, high ) =
    let
        clamp value =
            Basics.max -1.0 (Basics.min 1.0 value)

        toY value =
            (1.0 - clamp value) / 2.0 * height

        top =
            toY (clamp high)

        bottom =
            toY (clamp low)
    in
    { y = top, height = Basics.max 1.0 (bottom - top) }


view :
    { peaks : List ( Float, Float )
    , width : Float
    , height : Float
    , loop : Maybe { start : Float, end : Float }
    }
    -> Svg msg
view config =
    let
        count =
            List.length config.peaks

        barWidth =
            if count == 0 then
                0

            else
                config.width / toFloat count

        bar index pair =
            let
                { y, height } =
                    barFor { height = config.height } pair
            in
            Svg.rect
                [ A.x (String.fromFloat (toFloat index * barWidth))
                , A.y (String.fromFloat y)
                , A.width (String.fromFloat (Basics.max 0.5 (barWidth - 0.2)))
                , A.height (String.fromFloat height)
                , A.fill "#7aa2f7"
                ]
                []
    in
    Svg.svg
        [ A.viewBox ("0 0 " ++ String.fromFloat config.width ++ " " ++ String.fromFloat config.height)
        , A.width "100%"
        , A.height (String.fromFloat config.height)
        , A.class "waveform"
        ]
        (loopRegion config ++ List.indexedMap bar config.peaks)


loopRegion :
    { a
        | width : Float
        , height : Float
        , loop : Maybe { start : Float, end : Float }
    }
    -> List (Svg msg)
loopRegion config =
    case config.loop of
        Nothing ->
            []

        Just { start, end } ->
            [ Svg.rect
                [ A.x (String.fromFloat (start * config.width))
                , A.y "0"
                , A.width (String.fromFloat ((end - start) * config.width))
                , A.height (String.fromFloat config.height)
                , A.fill "#7aa2f7"
                , A.opacity "0.14"
                ]
                []
            ]
```

The loop region is drawn *before* the bars so the waveform sits on top of it.
